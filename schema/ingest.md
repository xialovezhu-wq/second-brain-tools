# ingest 工作流

创建日期：2026-06-28

## 目标

ingest 用于把新资料导入第二大脑：先保存或定位 raw source，再把有长期价值的内容沉淀进 wiki，最后更新索引和日志。

## 适用资料类型

| 类型 | raw source | wiki 去向 |
| --- | --- | --- |
| 日常状态 | `每日记录/YYYY-MM-DD.md`、`考研状态长期记录.md` | `节点/`、`关系/`、`决策索引.md`、`待确认问题.md` |
| 原始对话 | `原始对话/YYYY-MM.md` | 需要长期保留时再进入节点、关系或决策索引 |
| 学习过程 | `学习过程摘要/` | 高层模式进节点/关系；专项候选进待入库队列 |
| 专项同步包 | `索引/同步包索引.md`、相关每日记录或节点 | 科目节点、关系、待确认问题 |
| 长期主题 | 相关 raw source | `节点/`、`关系/`、`复盘/` |
| 决策事件 | 每日记录、原始对话 | `决策索引.md`、相关节点/关系 |

## 预读顺序

1. `AGENTS.md`
2. `第二大脑/00-运行规则.md`
3. `第二大脑/schema/00-LLM-Wiki运行规则.md`
4. 本文件
5. 与资料类型相关的目标文件

若涉及学习过程摘要，还要读取 `第二大脑/学习过程摘要/使用规则.md`。

## 执行步骤

1. 识别资料类型：日常状态、学习过程、专项同步包、长期主题或决策事件。
2. 确认 raw source 是否已经存在。
3. 若 raw source 不存在，按既有规则写入对应位置。
4. 从 raw source 中提取四类内容：已记录事实、用户自我假设、当前推断、待确认项。若事件将进入跨日关系判断，再按 `[[状态变量与证据协议]]` 分配事件 ID，并区分状态信号、暴露 / 行为、结果、调节变量和共同变量。
5. 判断是否有长期价值：
   - 跨日反复出现的行为或状态。
   - 影响考研学习、睡眠、训练、饮食、情绪或决策。
   - 能帮助未来回答“为什么”“是否应该”“下次怎么做”的信息。
6. 按去向写入，避免同一正文多处复制：
   - 长期稳定事实进入 `节点/`。
   - 关键事件的单次证据进入一个最相关的 `关系/` 日志。
   - 跨日候选、反例、共同变量和当前结论进入 `关系卡/`。
   - 跨日可复用的决策规则进入 `索引/决策索引.md`；一次性建议留在当日日记或关系卡反馈中。
   - 信息缺口进入 `索引/待确认问题.md`。
   - 学习专项候选进入 `学习过程摘要/待入库队列.md`。
7. 只有导航结构发生变化时才更新 `wiki/index.md`；不要把每次 ingest 复制成 index 更新行。
8. 在 `wiki/log.md` 追加操作记录。

## 写入边界

- 不把每日记录整体搬进节点。
- 不把完整聊天记录搬进 wiki。
- 不把专项错题的完整题干、完整解析、图片内容写入第二大脑。
- 不把单日现象直接写成稳定规律。
- 不把主观性欲强度、高刺激内容暴露、自慰行为和后续状态混为一个变量。
- 不把同一事件正文复制到多个关系页；使用事件 ID 和 wikilink 引用来源。
- 不为用户补编日期、分数、掌握度、来源、错因或因果关系。

## 日志格式

在 `wiki/log.md` 追加一行：

```markdown
| YYYY-MM-DD | ingest | 来源 | 更新文件 | 待确认项 | 状态 | 下一步 |
```

`状态` 使用：已完成、部分完成、待确认。

## 输出格式

完成 ingest 后回复：

- 本次识别：资料类型和系统边界。
- 已读取/参考：规则文件和 raw source。
- 已修改：raw source、wiki、索引、日志。
- 新增/更新内容：事实、节点、关系、待确认项。
- 校验：说明是否检查文件存在、表格列数或格式。
- 待补充：只列真实缺口。
