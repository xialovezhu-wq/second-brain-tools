# query 工作流

创建日期：2026-06-28

## 目标

query 用于基于第二大脑已有 wiki 和 raw sources 回答问题。回答必须可追溯，不能只凭记忆或单日印象。

## 预读顺序

1. `AGENTS.md`
2. `第二大脑/00-运行规则.md`
3. `第二大脑/schema/00-LLM-Wiki运行规则.md`
4. 本文件
5. `第二大脑/wiki/index.md`
6. 与问题相关的关系卡、节点、复盘、决策索引或待确认问题
7. 需要核对样本时读取 `关系/` 证据日志；证据仍不足时再回查 raw sources

## 查询路径

| 问题类型 | 优先读取 | 证据不足时回查 |
| --- | --- | --- |
| 今日怎么安排 | `决策索引.md`、相关关系卡、今日每日记录 | 关系证据日志、`考研状态长期记录.md`、最近每日记录 |
| 为什么最近状态差 | 相关关系卡、睡眠、饮食、分心节点 | 关系证据日志、每日记录、长期状态记录、原始对话 |
| 是否熬夜/咖啡因/训练 | 决策索引、睡眠节点、饮食补剂节点、训练关系 | 最近 3-7 天每日记录和状态记录 |
| 某科复习趋势 | 科目节点、学习过程摘要、同步包索引 | 专项同步包摘要、每日记录 |
| 行为模式复盘 | 关系卡、周复盘 | 关系证据日志、每日记录、原始对话 |

## 回答规则

1. 先说明使用了哪些第二大脑入口。
2. 回答中区分：
   - 已记录事实
   - 可观察趋势
   - 当前推断
   - 仍待确认
3. 不把 HRV、体重、单次学习时长、单次分心等单一指标作为完整结论。
4. 敏感内容只按中性行为模式回答，不展开露骨细节。
5. 如果涉及专项系统，只引用第二大脑中的高层摘要；不要假装已读取专项源数据。
6. 如果证据不足，明确说证据不足，并列出需要补充的 raw source。
7. 若涉及性欲，必须分别回答主观强度、实际行为、直接耗时和后续状态；缺哪一项就明确写缺失。

## 长期沉淀规则

若 query 形成了有长期价值的答案，应沉淀到 wiki：

- 稳定策略进入 `索引/决策索引.md`。
- 长期背景或状态进入 `节点/`。
- 单次证据进入 `关系/`；跨日当前判断进入 `关系卡/`。
- 未闭合事实进入 `索引/待确认问题.md`。
- 阶段性综合进入 `复盘/`。

沉淀后必须在 `wiki/log.md` 追加记录。若只是临时回答、没有修改文件，可以不写日志；若该 query 本身形成了重要结论但暂不沉淀，仍按 `query` 操作登记，并在“下一步”里注明 `query-only`。

## query-only 日志格式

```markdown
| YYYY-MM-DD | query | 问题或来源 | 无 | 待确认项 | 已完成 | 是否需要后续沉淀 |
```

## 输出格式

建议结构：

- 结论：直接回答问题。
- 依据：列出关键事实和引用的本地入口。
- 判断：区分趋势、推断和待确认。
- 建议：只给和问题相关的下一步。
- 是否沉淀：说明是否已写入 wiki；若未写入，说明原因。
