# LLM Wiki 运行规则

创建日期：2026-06-28

## 定位

本文件是第二大脑 LLM Wiki 的规则层入口，用来说明 raw sources、wiki、schema 三层如何协同。它不替代 `AGENTS.md` 和 `第二大脑/00-运行规则.md`；若规则冲突，优先级为：

1. `AGENTS.md`
2. `第二大脑/00-运行规则.md`
3. 本目录下的 LLM Wiki 规则
4. 具体模板、提示词和方案文件

## 三层定义

### raw sources

raw sources 是证据层，保存事实来源和接近原始材料的记录。包括：

- `第二大脑/原始对话/`
- `第二大脑/每日记录/`
- `第二大脑/学习过程摘要/`
- `考研状态长期记录.md`
- `第二大脑/索引/同步包索引.md`

维护原则：

- 能追加则追加，不反复重写。
- 同日事实可补录，跨日后优先作为证据读取。
- 不把 raw sources 整体迁移到新目录。

### wiki

wiki 是 AI 维护的 Markdown 知识层，用来沉淀长期主题、人物/角色、关系、模式、决策和状态变化。包括：

- `第二大脑/01-个人画像.md`
- `第二大脑/02-长期目标.md`
- `第二大脑/03-当前考研战略.md`
- `第二大脑/节点/`
- `第二大脑/关系/`
- `第二大脑/关系卡/`
- `第二大脑/复盘/`
- `第二大脑/索引/决策索引.md`
- `第二大脑/索引/待确认问题.md`
- `第二大脑/wiki/index.md`
- `第二大脑/wiki/log.md`

维护原则：

- 不重复复制 raw sources 正文。
- 长期主题进节点，事件级证据进 `关系/`，当前综合判断进 `关系卡/`，阶段性综合进复盘，决策入口进决策索引。
- `wiki/index.md` 只做导航和最近更新，不放完整结论正文。
- `wiki/log.md` 只记操作，不替代内容文件。

### schema

schema 是规则层，规定 AI 如何导入资料、回答问题、体检知识库。包括：

- `AGENTS.md`
- `第二大脑/00-运行规则.md`
- `第二大脑/schema/`
- `第二大脑/学习过程摘要/使用规则.md`
- `第二大脑/索引/` 下的模板、提示词和判断方案

维护原则：

- schema 只放规则和流程，不放日常事实、长期结论或用户隐私细节。
- 修改 schema 时要同步更新 `wiki/log.md`。
- Obsidian Bases 只作为派生看板，不替代 Markdown 来源；`scripts/second_brain_lint.py` 只读检查，不自动修复或改写 raw source。

## 通用操作原则

1. 先判断任务类型：第二大脑、长期状态记录、408、数学、英语，还是跨系统复盘。
2. 修改前先读取 `AGENTS.md`、`第二大脑/00-运行规则.md`、相关 schema 文件和目标文件。
3. 事实、用户自我假设、当前推断必须分开。
4. 缺失信息使用：未记录、未标明、待补充、待确认、待评分、暂无明确错因。
5. 敏感内容只中性记录时间、触发因素、来源类别、持续时间、影响和止损，不写露骨细节。
6. 专项错题、完整题干、完整解析和图片内容不进入第二大脑正文；只接收高层摘要和同步包。
7. 不迁移、不重命名、不批量整理旧文件。
8. 新增或更新 wiki 内容后，更新 `wiki/log.md`；只有导航结构变化时才更新 `wiki/index.md`。
9. 关系卡必须遵循 `[[状态变量与证据协议]]` 和 `[[关系卡/00-关系卡使用规则]]`，引用来源并保留反例与共同变量。

## 三个核心操作

| 操作 | 规则文件 | 什么时候使用 |
| --- | --- | --- |
| ingest | `ingest.md` | 用户提供新资料、每日记录、学习过程摘要或专项同步包，需要沉淀到 wiki |
| query | `query.md` | 用户基于第二大脑提问，需要调用历史背景、节点、关系和 raw sources 回答 |
| lint | `lint.md` | 定期检查孤立页面、矛盾结论、过期信息、缺少链接、未处理 raw source 和日志不一致 |
